Semantic Search

Adds meaning-based matching on top of keyword search, so “space movie with a robot” can find WALL·E. The model runs locally - no external service and no data leaves your server - but it downloads several hundred megabytes once and then costs CPU time for every indexed item. Leave it off unless you want that trade.
While this is off, nothing about embeddings is loaded or downloaded. Each model keeps its own download and its own vector cache, so switching away from one and back again costs neither - but the index has to be rebuilt after every switch, because vectors from one model mean nothing to another.
This server cannot run a local embedding model. The settings below have no effect until that is resolved; keyword search is unaffected. Set Embedding Model back to Off to stop the plugin retrying on every start.
When off, run the Download Meilisearch Embedding Model scheduled task instead.
0 is pure keyword search — the query is then not embedded at all — and 100 is pure meaning. Meilisearch picks one side per result rather than blending them, comparing keyword × (1 − ratio) against similarity × ratio. The catch is the scale: a keyword hit on a title scores 1.0, but similarity is reported as (cosine + 1) / 2, so an item with nothing to do with your query still scores around 0.7.

That puts the tipping point just under 60. Above it, every vaguely similar item outranks an exact title match, and typing the first words of a title pushes that title hundreds of results down. At 50 the keyword hits stay on top and the vector matches fill in underneath, which is what you usually want. Default: 50
How similar a result has to be before meaning-based search will return it. A vector search has no idea of “no match”: every item has some similarity to the query, so a query that matches nothing still fills the page. On the (cosine + 1) / 2 scale above, unrelated items sit near 0.7, so a floor only starts to bite around 72–78 — measured on a 330k-item library, where rank 100 of a vector search scored 0.70. Meilisearch applies a single threshold to both halves of a hybrid search, so this also raises the bar for keyword hits (the higher of this and Minimum Match Score wins); set it too high and weak keyword matches disappear with the noise. 0 disables the floor. Default: 0
How much of each item's metadata is embedded. Higher is slower. Default: 256

Changing this discards the vector cache and needs a full rebuild. A vector computed under one budget is not the one the next budget produces, so the cache starts over rather than handing the old vectors back, and the index keeps what it has until you rebuild.
0 uses half your CPU cores, leaving headroom for transcoding. Only applies to the CPU - a GPU provider schedules its own work. Default: 0
Leave empty unless you want to run embedding on a GPU. The plugin uses the fastest execution provider the loaded ONNX Runtime offers and falls back to the CPU, and the build shipped here is CPU-only.
The model is the largest thing this plugin keeps in memory. Releasing it after a quiet spell hands that memory back to playback and transcoding, at the cost of the next search: it is answered on keywords alone while the model reloads, and searches after it are semantic again. Default: 0
Stores vectors at one bit per dimension instead of a 32-bit float: about 32 times smaller, which keeps them in memory instead of read from disk on every search - seconds on a cold index. The trade is some ranking precision in the vector half of a search, and what it swaps in are near-ties, within roughly 1.5% of the similarity of what they replace. Keyword matching is exact either way.

Turning it back off needs a rebuild, since Meilisearch discards the full vectors as it compresses them - but that rebuild reads from the vector cache below, which always keeps full precision, so it re-uploads rather than re-running the model.
A rebuild re-embeds the whole library, and unchanged metadata gives an identical vector - the cache turns that back into a file read instead of hours of CPU. Costs about 4 KB per item, kept under Jellyfin's data directory. Leave this on unless disk space is tight.
A rebuild already drops cached vectors it no longer needs, so the cache follows your library's size on its own. Set a limit only to cap disk use. Default: 0 (unlimited)
Leave empty to store models under Jellyfin's data directory. Each model gets its own subdirectory.
Gives back the 1-2 GB the model holds without turning semantic search off, for a server that is not indexing right now. It stays unloaded until the next reindex, the next time you save this page, or a restart - searches run keyword-only in the meantime, and items synced while it is unloaded get no vector until the next rebuild.

Refused while a reindex is running: releasing the model underneath one would leave every item it still has to index without a vector, and a rebuild is meant to embed all of them or none. Cancel the task on the Scheduled Tasks page first if you mean it.
Throws away every cached vector so the next rebuild computes them from scratch. Changing the model or the token budget already does this on its own — reach for this when the vectors look wrong rather than merely stale, since every one it drops costs a forward pass to produce again, which is hours for a large library. The index keeps the vectors it already holds until you rebuild. Refused while a reindex is running.
After enabling this or changing the model, run “Rebuild Meilisearch Index”. Vectors are written as items are indexed, so existing documents have none until you rebuild.

Reconnect drops the current connection and dials Meilisearch again - useful after moving or recreating the server. Transient failures recover on their own.
